Cybersecurity Text Redactor A privacy-focused web application that detects and redacts sensitive personal information from documents while preserving their original format. PythonHTMLCSS

Background and development

I built Text Redactor to make removing sensitive information from documents simple and practical. Users can upload TXT, PDF, DOCX, or PPTX files, and the application scans the extracted text for common forms of personally identifiable information (PII), including Social Security numbers, financial information, email addresses, phone numbers, addresses, credentials, and IP addresses

Rather than automatically removing everything it detects, the application allows users to review the findings and choose what they want to redact before generating a protected copy. I also designed the redaction process around preserving the original document structure—for example, PDFs receive visual black redaction boxes while DOCX and PPTX content is masked in place. Uploaded and generated files are scoped to the user's browser session.

The application uses regular expressions (regex) to scan extracted document text for patterns associated with sensitive information, such as Social Security numbers, financial information, email addresses, phone numbers, IP addresses, and credentials. Flask handles the web application and file-processing workflow, while format-specific Python libraries process PDF, DOCX, and PPTX files and apply the selected redactions while preserving the document’s structure.

Governance, Risk, Compliance Automated GRC Dashboard for MediSync Solutions A simulated healthcare GRC environment combining security assessments, risk management, and Python automation to support compliance monitoring and audit readiness. HIPPANIST CSF 2.0ISO 27001:2022SOC 2Python

Background and development

I built this project around MediSync Solutions, a fictional healthcare SaaS company, to simulate the work involved in managing GRC in a highly regulated environment. I conducted NIST CSF 2.0 and ISO 27001:2022 assessments, developed a risk register using likelihood × impact scoring, mapped controls across multiple frameworks, and created security policies to support HIPAA compliance and audit readiness.

To take the project beyond manual compliance work, I built a Python-based automation layer that reads assessment and risk data from Excel workbooks, calculates compliance scores, identifies control gaps and risks above the organization's risk appetite, and prioritizes areas requiring attention. The system can also generate a risk heat map and a formatted PDF compliance report for executive or audit review.

I brought these components together in a Streamlit dashboard, transforming the assessment data into KPI cards, compliance progress indicators, risk filtering, and downloadable reports. The workflow is designed to simulate, at a smaller scale, the compliance monitoring processes used by enterprise GRC platforms—connecting traditional GRC analysis with automation and data-driven reporting.

Defensive Design and Attack Testing Secure Art Gallery Logging System A collaborative C++ security project that uses event logging and state validation to securely track gallery occupancy while defending against invalid input, unauthorized access, and file-based attacks. C++AES EncryptionInput ValidationState Machine LogicFile Locking

Background and Development

Developed collaboratively with a classmate, this project is a secure C++ logging system that tracks the movement of employees and guests through an art gallery. The gallery state is reconstructed from a sequence of logged events: each entry records who performed the action, whether they entered or left the gallery or a specific room, and when the event occurred. The system uses this history to determine each person’s current location and to generate information such as the gallery’s current occupancy and an individual’s room history.

We implemented state-based validation to make sure every new event is logically consistent with the existing log. For example, a person cannot enter a room before entering the gallery, enter a second room while already inside another, or leave a location they were never recorded as entering. This allows the application to reject invalid transitions instead of allowing them to corrupt the gallery’s state.

Security was also built into the file and input-handling mechanisms. We added token-based authentication to restrict access to log data, strict input validation and bounds checking to handle malformed or oversized input, filename validation to defend against path-traversal and resource-injection attempts, and file locking to protect the log during concurrent operations. We then tested these protections using intentionally invalid and adversarial inputs and strengthened the implementation based on the weaknesses we found.

Data Structures & Algorithms Data Structures & Abstraction in C++ A collection of C++ projects implementing fundamental data structures and algorithms from the ground up, with an emphasis on abstraction, memory management, testing, and reusable software design. C++Abstract Data TypesUnit Testing

Description

CS 23001 takes a deliberate approach to data structures: everything is built from scratch in C++, with no reliance on the Standard Library, so that the mechanics of how these structures actually work are fully understood rather than abstracted away. The course covers abstract data types, dynamic memory management, operator overloading, generic programming with templates, and fundamental structures including arrays, linked lists, stacks, and trees — all implemented by hand and validated through thorough unit testing.

Four substantial projects form the core of the course. Project 1 implements a Bigint ADT capable of arbitrary-precision integer arithmetic on numbers hundreds of digits long. Project 2 builds a fully dynamic custom string class with manual memory management and applies it to parse real Apache web server logs. Project 3 converts mathematical infix expressions into assembly code for a simple CPU — implementing the Shunting-Yard algorithm on a linked-list-backed generic stack, which uses the Project 2 string class throughout. Project 4, the most complex, reads C++ source code in XML format, constructs an Abstract Syntax Tree in memory, traverses it recursively, and rewrites the source to inject profiling counters.

Beyond the specific data structures, this course builds a practical understanding of how design decisions at the implementation level shape everything else. Choosing how to store data determines how hard every operation becomes — and getting that choice wrong has real consequences. Working through those tradeoffs in C++, from scratch, is what makes this course a strong foundation for systems programming, algorithms, and software engineering.

Software Design & Programming Patterns STL & Design Patterns in C++ A collection of C++ projects exploring object-oriented design, reusable software architectures, and common programming patterns through hands-on implementation. C++InheritanceSTLDesign Patterns

COMPUTER SCIENCE III - PROGRAMMING PATTERNS at Kent State

CS 44001 covers the design patterns and advanced C++ techniques that form the foundation of professional software engineering. The course works through the 23 patterns from the Gang of Four — the industry-standard catalogue every software engineer is expected to know — alongside the C++ Standard Template Library, generic programming with templates, move semantics, and the full inheritance and polymorphism model. These are not academic abstractions: design patterns are the shared vocabulary used in code reviews, architecture discussions, and system design interviews across the industry, and STL fluency is a baseline expectation for any C++ role.

The thirteen labs provide hands-on implementation of both. On the STL side, labs cover sequence containers (vector, deque, list), associative containers (map, set, unordered_map), STL algorithms including sort, find, transform, and accumulate, and move semantics through a custom move constructor. On the patterns side, labs implement all three pattern families directly in C++: creational patterns including Singleton, Abstract Factory, and Prototype; structural patterns including Adapter, Bridge, Decorator, Composite, Facade, and Flyweight; and behavioral patterns including Observer, State, Visitor, Command, Strategy, Memento, Chain of Responsibility, Mediator, and Template Method. Each lab requires writing the pattern from scratch — not applying a library — which means understanding the mechanism, not just the name.

Working through this course builds both a practical toolkit and a design instinct. Knowing when to reach for a Bridge versus an Adapter, or a State versus a Strategy, is what separates engineers who can implement features from those who can design systems. These labs demonstrate that capability concretely.

Operating systems Producer-Consumer Synchronization A C implementation of the Producer-Consumer problem using shared memory and semaphores to safely coordinate concurrent access to a limited shared resource. CShell TestingMake

Read more

This project implements the classic Producer-Consumer synchronization problem, modeling a challenge that appears whenever multiple processes or threads share limited resources. A producer generates items and places them into a shared table with only two available slots, while a consumer retrieves them. Because both operate concurrently, access to the shared table must be carefully coordinated to prevent conflicts and maintain a valid state.

We solved this using shared memory and semaphores to coordinate access between the producer and consumer, ensuring that items are produced only when space is available and consumed only when data is ready. The implementation was tested through repeated execution, high-load stress testing, and multiple producer and consumer threads to verify synchronization under different levels of concurrency.

Software Engineering & Educational Technology Gatekeeper — Interactive Digital Logic Learning Game A collaborative web-based educational game that teaches Boolean logic through interactive circuit-building challenges, real-time feedback, and sandbox experimentation. JavaScriptHTMLCSSSCRUM

Description

Developed collaboratively as a Software Engineering project, Gatekeeper was designed to make digital logic more interactive and approachable. Instead of learning Boolean logic only through static diagrams, users solve progressively harder circuit challenges by dragging and arranging logic gates, receiving immediate visual feedback as signals propagate through the circuit. A sandbox mode also allows users to freely build and experiment with their own circuits.

Behind the interface, we implemented the circuit simulation using JavaScript and p5.js. Logic gates maintain references to their input and output nodes and compute their output state from incoming Boolean values. To efficiently detect when nodes, gates, or components interact on the canvas, we used a spatial hash grid, allowing collision checks to be limited to nearby grid cells rather than comparing every object on screen.

We also built features including multilingual support, JSON export for user-created circuits, browser-based state storage, progressive levels, and visual feedback through the LUNA assistant. The project was developed using weekly Scrum sprints, a GitHub Kanban board, feature branches, pull requests, and peer code review.

To validate the application, we used unit and integration tests for core components such as draggable objects, collision detection, spatial hashing, and node-state transfer, alongside visual testing of circuit behavior.

Web Application Development WEDconnect — Wedding Management Platform A collaborative all-in-one wedding management platform that centralizes guest coordination, event information, reservations, and administrative planning into a single web application. JavaScriptAPI IntegrationData Analytics

A deep dive into WEDconnect

Developed collaboratively, WEDconnect was designed to replace the disconnected tools and manual coordination involved in planning and managing a wedding with one centralized platform. Guests can securely RSVP using invitation access codes, specify dietary restrictions, submit song requests, browse event information, reserve lodging, access registries, explore nearby places, and contribute photos.

The platform separates the guest experience from administrative management. On the administrative side, authenticated users can monitor RSVP activity through a dashboard, manage guest responses and dietary restrictions, moderate uploaded photos, review song requests, track wedding expenses and gifts, and manage lodging reservations.

Several workflows connect guest actions directly to planning needs. RSVP activity updates the administrative view, lodging reservations prevent the same listing from being double-booked, guest photos go through approval before publication, and gift records can be exported to CSV for use in creating thank-you cards. Together, these features turn WEDconnect into a practical event-management system rather than simply an informational wedding website.
